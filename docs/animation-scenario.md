## Плавніше перше збирання бланка — 2026-11-15

- `documentPhases.formSettleStart/End/Stagger` = 0.60 / 1.00 / 0.14. `formSettleExpr` генерує єдиний GLSL-розрахунок для фінального вирівнювання, масштабу, сплощення й проявлення master-друку. Затримка листка = до 0.12 за колонкою + до 0.02 детермінованої домішки за округленою клітинкою; індивідуальне вікно = 0.26. Усі листки сходяться до progress 1.
- Колишнє загальне замикання 0.84–0.985 та окремий швидкий прояв друку замінені поступовим складанням. Stamp lock, розпади, фоновий native stream-scatter, початковий автоматичний приліт, загальний easing і 1.8-секундне заповнення полів не змінювалися. На паузі всередині переходу бланк не завершує збирання самостійно; після повного складання запускається чинне заповнення.
- При перевірці resize після скролу виявлено пропуск перерахунку секцій: header/nav перепідписували callbacks у живому масиві event bus. Лише `global:resize` тепер обходить snapshot обробників; dispatch інших подій залишений поточним. Після виправлення 1920×1080 / 1024×768 / 390×844 зберігають extra=50svh, актуальні кеші секцій, 8 індексів і бюджет 300svh.

QA/кадри: `/private/tmp/qa-dala-hero-assembly*.mjs`, `/private/tmp/hero-settle-probe.js`, `/private/tmp/qa-dala-hero-scroll.mjs`, `/private/tmp/dala-hero-assembly-*`.

## Постійна хмара оригінального розльоту потоків — 2026-11-15

Це поточне рішення замінює великі фонові документи, три глибинні орбітальні плани та спільний вихор із попередніх записів. Користувач обрав живу хмару **після** розльоту потоків, без повторного вибуху на кожній сцені.

- `SurroundingDocuments` використовує ті самі геометрію, instance-атрибути, друк, масштаб і шейдери основних дрібних листків: 1600 desktop / 900 mobile. Обидва матеріали делегують складання оригінальним `onBeforeCompile`; окремої копії формул плавання/обертів немає. Великі `documentNear`-картки та орбіти вилучені з цього шару.
- Фоновий vertex shader читає усталений розсипаний target банку 2 із чинних позицій і `tParams3.x`, з поточним stream fit. Далі виконується наявний native vertex path: той самий масштаб банку 2, деформація, плавання, нахили й польоти. Нового FBO-циклу, моделей або текстур немає; основні формації та їхня симуляція не змінені.
- Фон плавно поступається видимій основній хмарі під час hero й розльотів; коли основна маса збирається або ховається для входу папки, дрібна хмара лишається навколо сцени. Внесок береться з фактичних eased uniforms і видимості, без таймера/перезапуску фонового шару.
- Плавні GPU-маски захищають бланк, п’ять потоків, документ із печаткою, фінальну сторінку/обкладинку та видимі DOM-тексти. Колір/depth мають спільні позиції, форму дрібного паперу й маски. Background uniform-и відокремлені від core; hero/hover/печатка/віза до фонових листків не застосовуються.
- Reduced motion фіксує час і параметри польоту, вимикає живе плавання. Початкова native hero-хмара й далі забезпечує спільний приліт; додатковий фон плавно входить, коли вона починає збиратися.
- На чинному сервері перевірені desktop 1440×900 / mobile 390×844, сцени 0→7, обидва фінали та A/B/C: однакова геометрія й native scale 2.95 / 2.7, WebGL error = 0, помилок JS/шейдерів немає. При однакових позиціях повний native color збігається піксель у піксель (max diff 0); прямий target порівняний із native FBO. Mobile FBO використовує half-float, тому лише порівняння усталених позицій має допуск на квантування; матеріал/розмір збігаються точно.
- GPU-перевірки підтвердили живий idle, точне відтворення кадру при тих самих входах і статичний reduced motion. У повному native-розльоті opacity додаткової хмари = 0, при прихованій основній масі = 1. Реальний wheel scroll із текстами, малими/великими кроками й трьома реверсами пройшов без GL/JS/шейдерних помилок.
- QA/референси: `/private/tmp/qa-dala-native-cloud*.mjs`, `/private/tmp/native-cloud-parity.js`, `/private/tmp/dala-native-cloud-*`. Оригінальний розліт — прогрес 3.28 із вимкненим попереднім оточенням. Весь код рушія поза `SurroundingDocuments` збережений. Production build та запуск/перезапуск сервера не виконувалися; фізичні пристрої не перевірялися. Після HMR може знадобитися повне оновлення сторінки через document-wide runtime singleton.


## Живий вихор фонового оточення — 2026-11-15

Ця зміна замінює фіксовані бокові траєкторії та попередню вимогу зберігати близькі фонові позиції. Основні формації й розльоти не змінені.

- `SurroundingDocuments`: збережені 96 desktop (48/32/16) та 36 mobile (18/12/6), наявні геометрія, атлас і один instanced mesh. Орбіти розраховуються з фіксованих дескрипторів, прогресу й часу без накопичення випадкового стану.
- Спільний кут проходить 0→π→2π→3π→4π на прогресі 0 / 1 / 2.8 / 3.8 / 6.2, потім до 4.5π на 7. Плавна інтерполяція з нульовою швидкістю на опорах; кут не скидається. Нерівномірний початковий кут створює трохи густіший бік, який змінюється між сценами. Листки мають різні радіуси, відставання та оберти, а чинний рух у глибину збережений.
- Повільні локальні дуги, радіальне плавання та оберти від часу продовжуються на паузі. Близькі листки рухаються по периметру, з переходами між сторонами через верх/низ. Світовий радіус залежить від глибини, щоб усі три плани лишались у кадрі, з перспективною зміною розміру й паралаксом камери. Плавні маски сторінки/тексту та спільна видимість color/depth збережені.
- Mobile зберігає повне перетікання між сторонами, із меншими локальними рухами й нахилами. Reduced motion фіксує позиції та оберти незалежно від скролу й часу.
- Headless Chrome на чинному localhost:3000: desktop 1440×900 та mobile 390×844; усі контрольні стадії 0→7 зберігають щонайменше 75% попередньої густоти (лічильник instance-видимості >0.05). Розподіл центрів зліва desktop на опорах: 59→39→57→41→59 із 96; mobile: 24→14→24→13→24 із 36. Три реверси при фіксованому часі повертають точні матриці; різниця на межах ±0.000001 прогресу ≤0.0000024. Рух на паузі й статичний reduced motion підтверджені.
- Перевірені обидва фінали та A/B/C, wheel input із повільними/великими кроками та реверсами на desktop/mobile. WebGL error = 0, помилок JS/шейдерів немає. Весь код поза `SurroundingDocuments` побайтово збігається зі станом перед цією зміною. QA/кадри: `/private/tmp/qa-dala-vortex.mjs`, `/private/tmp/dala-vortex-*`. Фізичні пристрої не перевірялися. Production build і запуск/перезапуск сервера не виконувалися.

## Повернення потоків і просторові переходи — 2026-11-14

Це актуальне рішення замовника замінює записи про видалення потоків і бюджет двох екранів нижче.

- Послідовність: hero → бланк → розліт → **п'ять потоків** → розліт → документ із печаткою → розліт → фінал «Папка/Документ».
- Потоки збираються на 2.45–2.75, тримаються до 3.05, розлітаються на 3.05–3.22; плавання до 3.4, печатка збирається на 3.4–3.65. Індекси секцій, автоматичне притискання та окреме відкриття папки збережені.
- Повна ділянка 1.8–3.4 має **300svh** разом із сусідніми відступами; приховані додаткові текстові блоки не повертаються. Заголовок — `Document flows`.
- Банк 2 знову містить п'ять хвилястих доріжок із детермінованим випадковим вибором, власними масштабами й кольорами. Підсітки 40×40 / 30×30 не втрачають три доріжки через кратність індексів. Формація вписується в розмір камери; банки сторінок не масштабуються цим налаштуванням. EXR — без стиснення.
- Кожен перехід отримав індивідуальні оберти та спіральні дуги XYZ. Накопичуваний `flightPhase` проходить 0→4 без скидання; `flightArc` точно нульовий на стабільних кадрах. Колір і depth використовують один vertex-код та спільні uniform-об'єкти. Папка також отримала спіральний підліт і нахили листків; A/B/C сходяться до поточного фіналу.
- Mobile: половинна амплітуда і поворот-погойдування із поверненням у вихідну орієнтацію. Reduced motion: нові польоти й обертання вимкнені, розліт ≤0.12. Кількість частинок і чотири банки збережені.
- Оновлено сценарії таймлайна для потоків, пауз, реверсу й стабільних обертів. Підсумкова перевірка обмежена TypeScript та ESLint змінених файлів за AGENTS.md; браузерні результати старих записів не підтверджують цю зміну. Візуальні критерії: п'ять доріжок на 1512×805 / 1920×1080 / 390×844, повільний/швидкий скрол і три реверси, hover, A/B/C та обидва фінали. Production build і запуск/перезапуск сервера не виконуються.

### Контекст
Після перегляду поточної анімації замовник надиктував зміни: hero-смуга документів з «прилипанням» до миші, зібраний документ має бути анкетою-бланком з фото, далі «документальні потоки» (черга) → штамп (обробка) → документи злітаються в папку → у фіналі папка відкривається, всередині «віза», складена з документиків.
Рішення користувача:
1. Крок «документи злітаються в папку» — **лишаємо як зараз зроблено**, доробимо після рішення.
2. Фінал папки — **реалізуємо 3 варіанти з перемикачем**, щоб порівняти.
3. Документики складають англійське **`VISA`**; літери — **Deep Navy `#041E42`** (синій бренду проєкту).

Що вже є і що перевикористовуємо: FBO-симуляція 10k точок + 4 банки позицій (`legacy/2601.cjs`, `an`), генератор формацій `scripts/generate-document-particles.mjs`, SVG→PNG генератори на `sharp` (`scripts/generate-document-atlas.mjs`, `scripts/generate-master-document-example.mjs` — сітка 40×40 майстер-документа), мозаїчна підсітка `an._grid`, мишачий hover у вершинному шейдері `tn` (replace на :4156), панель `?tune` (`app/DevTuner.tsx`, lil-gui).

### Реалізація

#### 1. Формації та кольори — `scripts/generate-document-particles.mjs`

## 6. Критерії приймання, QA, ризики й відкриті рішення

Цей розділ перетворює опис руху на перевірювану специфікацію. Нові пропозиції, яких користувач прямо не затверджував, позначені як **рекомендація** і не мають непомітно змінювати артдирекцію.

### 6.1. Інваріанти всього сценарію

- Цільові transform, visibility та фази обчислюються з `sectionProgress`. Через spring/FBO результат може коротко залежати від швидкості скролу, але після стабілізації сходиться до того самого стану; одноразових незворотних таймерів немає.
- Між активними інтервалами стан утримується без стрибка. Зокрема: `1.0–1.8`, `2.2–2.7`, `3.0–3.3`, `4.42–4.5`, `5.0–5.7` — hold-зони, якщо в журналі явно не вказано інше.
- Кожна нова сцена має коректно переживати resize, зміну DPR і повернення на вкладку без `NaN`, чорного кадру та повторної ініціалізації об'єктів.
- Тимчасові dev-контроли не змінюють вигляд без параметра/вибору, не перекривають основний контент і не потрапляють у фінальний production UI після затвердження варіанта.
- Палітра паперу: Warm Ivory `#F6F2E9`, Deep Navy `#041E42`, Classic Champagne `#D6BE93`. Червоний відбиток — окреме незатверджене виключення.
- Немає читабельних персональних даних, брендів або випадкового AI-тексту на документах; форма використовує псевдотекст.

### 6.3. Контракт фіналу A/B/C

Спільна частина:

- Один клас/граф `Folder` і один фінальний layout; не робити три копії геометрії або три незалежні кінцеві сцени.
- Локальний прогрес фіналу: `finalT = clamp((sectionProgress - 5.7) / 0.3, 0, 1)`. Конкретні easing можуть різнитися, але при `finalT = 1` результат піксельно зіставний.
- `u_visaReveal` відповідає тільки за прояв кольорової маски `VISA`. Він не повинен випадково перефарбовувати попередню анкету чи потоки.
- Маску будувати з урахуванням фактичної видимої підсітки `an._grid` 40×40, а не лише повної FBO-сітки 100×100. Штрихи літер — не тонші за дві видимі клітинки; sampling — без розмиття між navy та папером.
- Генерація маски детермінована й не залежить від системного шрифту. Або використати зафіксований шрифт/контури, або описати літери геометрично.

Відмінності варіантів:

| Варіант | Унікальна дія | Додаткова умова приймання |
|---|---|---|
| A — «Переворот» | Папка під'їжджає, обертається на 180° по Y, потім відкривається. | Після перевороту `VISA` не дзеркальне; вміст не просвічує крізь закриту обкладинку. |
| B — «Розліт» | Листки дають локальний сплеск і збираються у `VISA` вже в папці. | Сплеск не змінює `u_explode` в інших секціях і повністю заспокоюється до `6.0`. |
| C — «Під'їзд» | Папка виїжджає збоку й обкладинка відкривається як книжка. | Папка не перетинає фінальний текст і не виходить за safe area на 16:9 та 16:10. |

Контракт перемикача:

- URL `?folder=a|b|c` — джерело істини для відтворюваних посилань і скріншотів; невалідне значення безпечно дає preview A, але не означає, що A обрано фінальним.
- Сегмент-контрол і dropdown у `DevTuner` синхронізовані в обидва боки та зберігають інші query-параметри (`?tune`, `?logs` тощо).
- Перемикання не створює нові WebGL-об'єкти щоразу й не потребує reload.
- Контрол доступний з клавіатури, має видимий focus і зрозуміле accessible name. Поза фінальною секцією він прихований і не перехоплює pointer events.
- Перемикач видаляється лише після явного вибору замовника; до цього жоден варіант не називати «основним» у UI або кодових коментарях.

### 6.4. Responsive, accessibility і performance — рекомендації

Ці вимоги рекомендовані як безпечний production-baseline; вони не змінюють затверджену desktop-артдирекцію.

- **Mobile:** зберегти сюжет «смуга → анкета → потоки → обробка → папка → `VISA`», навіть якщо складні ефекти спрощені. Mouse-attract лишається вимкненим; печатка має спрощену безпружинну версію.
- **Reduced motion:** для `prefers-reduced-motion: reduce` вимкнути mouse-attract, flutter, сильний explode і пружні відскоки; показати стабільні ключові композиції з коротким crossfade або статичним постером. Це ще треба погодити візуально.
- **Performance-budget:** заміряти 10 секунд у точках `0`, `4.0`, `6.0`. Орієнтир — p95 frame time ≤20 ms на типовому desktop і ≤33 ms на сучасному mobile; якщо поточний baseline гірший, новий крок не має погіршити його більш ніж на 10% без зафіксованої причини.
- Не додавати окремий 4K-атлас для кожного варіанта папки. Перевикористовувати геометрію, матеріали й маску кольору.
- Перевірити DPR 1 і 2 окремо: підвищення `setPixelRatio` не приймається як єдине виправлення розмиття, якщо воно суттєво б'є по frame time.

### 6.7. Відкриті рішення

Не блокують реалізацію трьох preview-варіантів:

1. Який фінал залишити: A, B чи C — вибирає замовник після живого порівняння.

4. Чи лишається червоний відбиток, чи переводимо його в брендовий Deep Navy.
5. Наскільки повною має бути сцена печатки на mobile.
6. Який reduced-motion fallback затвердити: ключові WebGL-кадри чи статичний постер.

### 6.8. Definition of Done

**Milestone «порівняння фіналу» готовий**, коли A/B/C проходять спільні критерії, відкриваються прямими URL, синхронно перемикаються без reload, мають однаковий кадр на `6.0` і не ламають попередні сцени.

**Production-фінал готовий**, коли замовник обрав варіант; тимчасовий перемикач прибраний; погоджені mobile/reduced-motion і копірайт; пройдена QA-матриця; збережені контрольні скріншоти; `CLAUDE_HANDOFF.md` та цей журнал відповідають коду; усі команди перевірки проходять без нових помилок.

Магніт має попередню силу 0.72 й залишається активним під час проведення. Розліт накладається після нього в екранних координатах, однаково для основного/переднього шарів і кольору/глибини. Радіус 45 px, поштовх до 50 px; обмежена історія 16 відрізків із об'єднанням до 80 мс зберігає плавний слід. Аналітична критично загасаюча пружина повертає зміщення в нуль до 1.15 с, нерухома миша нових впливів не створює. Старий поштовх у GPU-проході швидкостей прибрано; базова симуляція збережена, нових FBO/ассетів/проходів немає. Ціна нового способу — обмежений цикл у vertex shader.

Окремий лічильник руху запобігає поштовхам від кліку, завантаження, resize чи повторного входу. Blur, вихід курсора, приховування вкладки й вихід із hero очищають слід. Пізніші сцени зберігають поточну поведінку.

**Перше наведення перевірено в браузері:** EXR-ассет тимчасово затримано, справжню позицію миші передано під час завантаження, після чого курсор лишався нерухомим. Обидва шари активували магніт після готовності із нульовою кількістю кліків та `document.hasFocus() = false`. Невідома позиція чекає першого наведення; початкова позиція не створює штучного поштовху. Рух зберігає магніт, нерухомий курсор не додає слідів, blur і повторне наведення без кліку працюють, живий reduced motion вимикає реакцію. Нових JS/GLSL-помилок немає, `gl.getError() = 0`. QA: `/private/tmp/qa-dala-hero-first-hover.mjs`, кадр `/private/tmp/dala-hero-first-hover.png`; використано наявний localhost:3000 без build або перезапуску. Ширший візуальний/mobile QA нового сліду та Node test runner залишаються непроведеними; старі перевірки зміщень FBO не застосовуються до нового post-magnet ефекту.


### Перша хмара: власна фізика листків без сліду — 2026-11-13

Узгоджено: листки самостійно хаотично плавають; рух миші лише відштовхує їх; після поштовху нове місце зберігається. Наведення на один листок протягом 1000 мс активує тільки його магніт; подальший рух відпускає й відштовхує. До 3 px тремтіння курсора ігнорується, для утримання кандидата є допуск 8 px. Клік і фокус сторінки не потрібні.

`hero-motion.cjs` зберігає швидкість, зміщення й поворот кожного листка. Радіус поштовху 45 px; швидкість 180–260 px/с з максимумом 320, експоненційне гасіння 5/с. Стан належить листку, а не пройденому маршруту: масив 16 відрізків і старий шейдерний слід видалені. М'яка межа тримає взаємодіяні листки поблизу viewport, не повертаючи їх у початкові точки.

Позиції основного шару підхоплюються з симуляції один раз після вступу, масштаб кешується один раз. Обидва шари отримують готову позу й quaternion через instanced attributes; освітлення, колір, глибина та вибір листка узгоджені. Ліміт атрибутів збережений завдяки відновленню ID із UV. Нових FBO, draw calls, ассетів і читання GPU на кожному кадрі немає. Вступ має плавне підхоплення 150 мс; реакція вимикається на початку збирання, поза згасає на 0.1→0.46. Reverse entry починає нову хмару після повернення; інші сцени не використовують нову фізику.

Перевірено у браузері sharp/current: поштовхи, збереження нового місця після згасання швидкості, секундний dwell, рівно один магніт, відпускання, blur, перехід в анкету, reverse entry, resize, живий reduced motion; `gl.getError() = 0`, нових JS/GLSL-помилок немає. QA: `/private/tmp/qa-dala-hero-physics.mjs`. Build і перезапуск сервера не виконувалися.

### Перша хмара: mousemove без кліку й магніт після короткої паузи — 2026-11-13

Замість секундного dwell: останній реальний рух запускає паузу 150 мс, потім вибирається один видимий листок у межах 100 px — спершу безпосередньо під курсором, інакше найближчий. Захоплення стабільне до нового руху, а не залежить від старого hitbox. Наростання магніту — 200 мс. Рух понад 3 px відпускає листок, і тільки новий відрізок руху дає поштовх.

Радіус лишився 45 px; швидкості подвоєно до 360–520 px/с, максимум 640. Під час руху гасіння 5/с, після паузи — 30/с, щоб залишковий відліт згасав приблизно за 100 мс. Нові місця та фонове плавання збережені, маршруту курсора немає.

Ранній трекер v2 слухає обидві родини mouse/pointer-подій, не подвоює рух при їхньому спільному надходженні, ігнорує touch compatibility events і підтримує перевстановлення старого HMR singleton. Звичайний mousemove працює навіть за наявності PointerEvent; клік або фокус не є умовою запуску.

Логіка фактичних CJS-модулів перевірена в пам'яті: mouse-only наведення, парні події, повторна установка/очищення, touch-фільтрація, пауза й стабільний магніт на 30/60/120 fps. Браузерний QA поки не виконаний: попередній localhost:3000 зупинений, запуск за AGENTS.md потребує явного прохання користувача. Build і запуск сервера не виконувалися.


### Одноразовий автоматичний запуск без перезапуску від кліку — 2026-11-13

Замість штучного DOMContentLoaded `ScriptLoader` викликає `startDala()` з `entry.cjs`. Збережений на window runtime повертає ту саму обіцянку запуску та володіє єдиними renderer, RAF і вступом. Повторні виклики, remount і повторний DOMContentLoaded не створюють нової сцени. Позиція курсора під час завантаження зберігається; після прильоту обидва шари готуються автоматично, натискання не потрібне.

Трекер v3 не слухає кнопки миші. Blur окремого елемента не означає виходу миші зі сторінки. Скидання вводу звільняє магніт, але не вимикає готову позу, не перестворює контролер і не перечитує стартові позиції. Resize та приховування вкладки зберігають фізичні зміщення; власний годинник плавання/підхоплення не накопичує час у прихованій вкладці. Лише реальний вихід із hero або reduced/coarse/mobile вимикає фізику; явний replay у DevTuner лишається доступним.

У браузері sharp перевірено: звичайний loader без skiploader, наведення під час вступу й магніт без натискань, повторний start, повторний DOMContentLoaded, справжній клік із незмінними renderer/контролером/capture count/u_show, blur/re-entry, resize, hidden/visible, перехід в анкету, reverse та живий reduced motion. `gl.getError() = 0`, нових JS/GLSL-помилок немає. ### Безперервна хмара: реакція поверх початкової анімації — 2026-11-13

Причиною видимого «перезавантаження» була не нова ініціалізація runtime, а заміна кожної WebGL-пози, орієнтації та масштабу на CPU-позу через 150-мс blend після вступу. `a_heroPose`, `a_heroRotation`, `u_heroPoseMix`, окремий CPU-годинник і handoff прибрані.

Початкова GPU-симуляція, повороти, масштаби й плавання працюють безперервно. Атрибут `a_heroInteraction`, нульовий ще до першого кадру, містить лише зміщення XY, додатковий spin та вагу магніту. Blur/re-entry, resize, анкета/reverse та живий reduced motion пройдені, нових JS/GLSL-помилок немає, WebGL error — 0. QA: `/private/tmp/qa-dala-continuous-hero.mjs`.
